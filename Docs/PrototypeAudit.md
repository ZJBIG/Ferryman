# V0.1 策划覆盖与验证

已逐条核对《可玩原型策划案 (程序主要参考).docx》的正文、路线图，以及《美术需求文档.docx》的资源和 UI 表。文档用于确定功能范围，用户确认的维修参数和存档修订优先执行。

本轮范围为整个首版可玩原型：战斗、船损维修、固定 NPC 岗位、自动航程、事件、上下客、奖励结算和强退恢复。第 10 章明确首版暂不加入商店与永久成长；特殊岗位能力未定义，保留为后续内容。

## 用户确认的规则

- 按住 E 维修；1 单位甲板网格，切比雪夫范围 1 格，同时 1 点，50 HP/s。
- 维修点逐圈搜索新的距离层，可扩散全甲板；并行维修不分摊速度。
- 主动放弃、正常关闭游戏丢弃本轮；强退或崩溃从自动检查点恢复。
- 使用现有工作区，保留已有修改；允许必要重构，简单字段、属性和输入读取不新增测试。
- 已接入 `场景.zip`，按船原画配置镜头与甲板边线。舱体分段阻挡，左上和左下保留通行空间，边线沿船头内栏杆闭合。原 12×5 网格在船头侧增加 3 列，旧检查点格索引兼容。移动回归覆盖进入和离开船头，船损回归覆盖船头炸弹和落石着陆、维修进度恢复及旧边缘破损重定位。
- 用户要求删除截图中的六块航程 HUD 及专用内容；本轮不设计新 UI，后续由用户定义。途中乘客岗位/目的地数据和上船等待保留，旧 HUD 的预告显示已移除。
- 完整游戏整合为 main；出发到结算、恢复与返家在同一场景内完成。交付帧动画全部接入，静态素材保持静态。
- 已接入 `物品与维修.zip` 的 9 张静态素材，编号作为外观样式；维修 Slider 满格须覆盖整个内框，左右上下不留空隙。README 与 GitHub 简介只保留玩家玩法与操作介绍。

## 数据与恢复边界

采用 ScriptableObject，无新输入、镜头、事件总线或对象池依赖。完整入口为 main，默认航线为出发岛 → 近海 → 途中岛 → 外海 → 最终岛。main 按路线 `sceneName` 映射岛屿显示，整轮不重载场景；原 Departure、Sea、Island、FinalIsland 保留为演示，Prototype 仍作为独立战斗/维修夹具。默认船员数值是可调的原型配置，不表示未来成长价格或正式平衡已经定案。

检查点在启航时立即建立，并在区域抵达且上下客完成后保存。保存种子、区域、玩家/乘客位置与目的地、船 HP、累计余数、维修点格/位置/进度、临时奖励和已送达人数。恢复时重新进入保存区域，海路敌人与炸弹从该区域开始重新执行；不保存逐帧敌人或炸弹状态。

永久奖励只在成功/失败时写入，文件通过临时文件替换提交。结算后遗留的同航程检查点会被去重清理，主动退出只丢弃本轮检查点。错误配置在启航前检查；损坏存档显示错误且不覆盖已有永久数据，结算写入失败可重试。
